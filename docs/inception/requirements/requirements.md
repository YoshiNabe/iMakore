# iMakore (イマコレ) — 要件定義書

## 1. インテント分析

| 項目 | 評価 |
|---|---|
| **ユーザーリクエスト** | 今どのプロジェクトの業務を行っているかを把握し、始業から終業まで各プロジェクトへの稼働時間をボタン操作で記録するWebアプリの作成 |
| **リクエストタイプ** | New Project（グリーンフィールド） |
| **スコープ** | System-wide（新規 Web アプリ全体） |
| **複雑度** | Moderate（リアルタイム時間計測・ローカルストレージ永続化・内蔵カレンダービュー） |

## 2. 機能要件

### FR-01: プロジェクト登録

プロジェクトを新規登録できる。登録フォームで以下の情報を入力する。

- **プロジェクト名**（必須）: 表示名。ボタンのラベルとして使用する。
- **プロジェクトコード**（任意）: 社内プロジェクト管理コード。既存の命名規則・プロジェクト番号に合わせた識別子。

### FR-02: プロジェクト削除

登録済みプロジェクトをメニューから削除できる。削除前に確認ダイアログを表示し、誤操作を防ぐ。削除時は、そのプロジェクトの過去の時間記録はカレンダー履歴として保持する。

### FR-03: 作業セッション管理

1 日の作業を始業から終業まで漏れなく記録するため、以下のボタンを画面に配置する。

- **始業ボタン**: アプリ起動後に押すと作業セッションを開始する。始業後は必ず 1 つのプロジェクトボタンがアクティブな状態を維持する。
- **プロジェクトボタン**: 登録されたプロジェクトごとに 1 つずつ表示する。ボタンを押すとそのプロジェクトの計測を開始し、前にアクティブだったプロジェクトの計測は停止する。
- **終業ボタン**: 押すと現在アクティブなプロジェクトの計測を停止し、セッションを終了する。終業後はどのプロジェクトボタンもアクティブでなくなる。

### FR-04: リアルタイム経過時間表示

現在アクティブなプロジェクトボタンには、そのセッション開始から現在までの経過時間をリアルタイム（毎秒更新）で表示する。

### FR-05: 当日累積時間表示

各プロジェクトボタンに、その日の累積稼働時間（HH:MM:SS 形式）を表示する。累積時間には、複数回の切り替えで積み上がった時間の合計を示す。

### FR-06: 日次リセット

毎日 0 時（深夜 0 時）に、全プロジェクトの当日累積時間を自動的にリセットする。リセット前の当日データは、日次履歴としてカレンダービュー用に保存する。

### FR-07: カレンダービュー（集計確認）

アプリ内に月カレンダー形式の集計ビューを内蔵する。外部カレンダーサービスは使用しない。カレンダービューの仕様は以下のとおりである。

- 月単位のカレンダーを表示し、前月・次月に移動できる。
- 各日付セルには、その日の総稼働時間（全プロジェクト合計）を表示する。
- 日付セルをタップすると、その日のプロジェクト別内訳（プロジェクト名 / コード / 稼働時間）を表示する。

### FR-08: メニュー機能

画面上にメニューボタンを配置する。メニューから以下の機能を選択できる。

- プロジェクト登録（FR-01）
- プロジェクト削除（FR-02）
- カレンダービュー表示（FR-07）

### FR-09: データの端末保存

すべての履歴・設定はブラウザの `localStorage` を使用して端末側に保存する。ネットワーク接続がない状態でも完全に動作する。保存対象は以下のとおりである。

- 登録済みプロジェクト一覧（名前・コード）
- 日次集計履歴（日付・プロジェクト別稼働時間）
- アプリ設定（将来拡張用）

## 3. 非機能要件

### NFR-01: 配信・デプロイ

GitHub Pages でホスティングする。URL 形式は `https://<GitHubユーザー名>.github.io/iMakore/` とする。ソースコードは GitHub リポジトリ `iMakore` で管理する。

### NFR-02: 技術スタック

バニラ HTML/CSS/JavaScript のみを使用する。フレームワーク・ビルドツール・外部依存パッケージは使用しない。GitHub Pages に直接配置できる静的ファイル構成とする。

### NFR-03: データストレージ

`localStorage` を使用してすべてのデータを端末側に保存する。サーバーへのデータ送信は行わない。ストレージ容量の上限（概ね 5 MB）を超えないよう、履歴データは適切に管理する。

### NFR-04: モバイルフレンドリー

スマートフォン・タブレット・PC のいずれのデバイスでも快適に操作できるレスポンシブデザインを採用する。ボタンは指でタップしやすい十分なサイズで配置する。

### NFR-05: オフライン動作

インターネット接続なしで全機能が動作する。

### NFR-06: タイマー精度

アクティブなプロジェクトの経過時間は毎秒更新する。ブラウザのタブが非アクティブ状態や PC がスリープ状態から復帰した場合でも、時刻ベースの計算により正確な経過時間を表示する。

## 4. ユーザーシナリオ

### シナリオ A: 通常の 1 日の記録

1. 朝、アプリを開く。「始業」ボタンを押して作業を開始する。
2. 最初に取り組むプロジェクトのボタンを押す。そのボタンがアクティブになり、経過時間の計測が始まる。
3. 別のプロジェクトに切り替えるときは、そのプロジェクトのボタンを押す。前のプロジェクトの計測が停止し、新しいプロジェクトの計測が始まる。
4. 退勤時に「終業」ボタンを押して計測を終了する。
5. 翌朝 0 時に前日分の累積データが日次履歴に保存され、当日の累積がリセットされる。

### シナリオ B: 過去の実績確認

1. メニューからカレンダービューを開く。
2. 月カレンダーを操作して確認したい月を表示する。
3. 任意の日付をタップしてその日のプロジェクト別内訳を確認する。

### シナリオ C: 新規プロジェクト追加

1. メニューから「プロジェクト登録」を選択する。
2. プロジェクト名（必須）と社内プロジェクトコード（任意）を入力する。
3. 保存すると、メイン画面に新しいプロジェクトボタンが追加される。

## 5. 拡張機能設定

| 拡張機能 | 有効 | 決定根拠 |
|---|---|---|
| Visual Enhancement | 無効 | ユーザー選択（テキストのみの成果物で十分）|
| External UI Spec | 無効 | ユーザー選択（AI-DLC ネイティブ動作）|
| Security Baseline | 無効 | ユーザー選択（プロトタイプレベル）|
| Property-Based Testing | 部分適用 | 純粋関数・シリアライゼーションのみ |
| Step Process | 無効 | ユーザー選択（AI-DLC ネイティブ Unit 単位）|
