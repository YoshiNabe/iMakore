# iMakore U1-core — ビジネスルール

## BR-01: プロジェクト登録バリデーション

**適用タイミング**: プロジェクト追加フォームの送信時

| フィールド | ルール | エラーメッセージ |
|---|---|---|
| `name` | トリム後に 1〜50 文字であること | 「プロジェクト名は必須です（50 文字以内）」|
| `code` | null 可。入力時はトリム後に 1〜20 文字であること。トリム後が空文字の場合は null として扱う | 「プロジェクトコードは 20 文字以内で入力してください」|

---

## BR-02: セッション状態遷移

| 遷移 | トリガー | 事前条件 | 事後状態 |
|---|---|---|---|
| IDLE → ACTIVE | 始業ボタン押下 | プロジェクトが 1 件以上登録されていること | ACTIVE |
| ACTIVE → IDLE | 終業ボタン押下 | ACTIVE 状態であること | IDLE |
| ACTIVE → ACTIVE | 別プロジェクトボタン押下 | ACTIVE 状態かつ押下したボタンが現在と異なるプロジェクトであること | ACTIVE（プロジェクト切り替え）|

**特殊ケース:**
- プロジェクトが 0 件の場合、始業ボタンは視覚的に無効化し、クリックしても遷移しない。メニューからプロジェクトを追加するよう案内する。
- ACTIVE 状態で現在のプロジェクトボタンを押しても何も起こらない（同一プロジェクトへの切り替えは無視）。

---

## BR-03: 始業後の初期プロジェクト選択

始業ボタン押下後、プロジェクト一覧（登録順）の先頭（インデックス 0）のプロジェクトを自動でアクティブにする。ユーザーはその後任意のプロジェクトに切り替えられる。

---

## BR-04: 日次ロールオーバー（次操作時）

`checkAndRollover()` を以下のタイミングで呼び出す。

1. アプリ起動時（`AppController.init()` 内）
2. 始業ボタン押下時
3. プロジェクト切り替え時
4. 終業ボタン押下時

**ロールオーバー判定と処理:**

- `SessionSnapshot.sessionDate` または DailyAccumulator 内の基準日が今日の日付と異なる場合、ロールオーバーが必要と判定する。
- ロールオーバー処理:
  1. DailyAccumulator が保持する当日累積データを `imakore_daily[旧日付]` として StorageService に保存する。
  2. DailyAccumulator の当日累積カウンターをリセット（全プロジェクト 0 秒）する。
  3. 基準日を今日の日付に更新する。

---

## BR-05: セッション復元（アプリ起動時）

アプリ起動時（`AppController.init()`）に `imakore_session` を読み込み、以下の分岐に従う。

| 条件 | 処理 |
|---|---|
| `imakore_session` が null | IDLE 状態で起動する |
| `sessionDate` == 今日の日付 | `projectStartTimestamp` からの経過時間でタイマーを復元し、ACTIVE 状態で起動する |
| `sessionDate` != 今日の日付 | BR-04 のロールオーバー処理を実行した後、セッションをクリアして IDLE 状態で起動する |

---

## BR-06: タイマー計算

経過秒数は `setInterval` の精度に依存せず、常に `Date.now()` 差分で計算する。これにより、スリープ復帰後やタブ非アクティブ後も正確な値を保つ。

```
elapsedSeconds = Math.floor((Date.now() - projectStartTimestamp) / 1000)
```

累積表示（アクティブプロジェクト）:

```
displaySeconds = DailyAccumulator.getTodayAccumulated(projectId) + elapsedSeconds
```

## BR-07: プロジェクト削除と履歴保持

プロジェクト削除は以下の手順で行う。

1. **削除制約**: 現在 ACTIVE 状態でアクティブなプロジェクトは削除できない。削除ボタンは表示するが、選択時に「終業後に削除してください」のメッセージを表示する。
2. **削除処理**: 削除確認後、`imakore_deleted[projectId] = project.name` に名前を記録してから `imakore_projects` の配列からプロジェクトを除外する。
3. **カレンダー表示**: `imakore_daily` のエントリに削除済みプロジェクトの ID が含まれる場合、`imakore_deleted` から名前を取得して「[削除済み] プロジェクト名」の形式で表示する。

## BR-08: ボタン表示ルール

| 状態 | 始業ボタン | 終業ボタン | プロジェクトボタン |
|---|---|---|---|
| IDLE（プロジェクト 0 件）| 表示・無効（グレーアウト）| 非表示 | なし |
| IDLE（プロジェクト 1 件以上）| 表示・有効 | 非表示 | 表示・非アクティブ（操作しても何も起きない）|
| ACTIVE | 非表示 | 表示・有効 | 1 つがアクティブ（ハイライト + 経過時間表示）、他は非アクティブ（累積時間のみ表示）|

---

## BR-09: 時間表示フォーマット

| 秒数 | 表示形式 | 例 |
|---|---|---|
| 0〜3599 秒 | `HH:MM:SS` | `00:12:34` |
| 3600 秒以上 | `HH:MM:SS`（時間は 2 桁以上）| `01:05:00`, `10:30:45` |

カレンダーの日付セルには合計時間を `H:MM` 形式で表示する（省スペース）。
